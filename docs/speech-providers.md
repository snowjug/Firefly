# Speech providers

Reference for the server's speech layer: the three provider kinds, every environment variable, the three endpoints, what is sent to the speech service and what is not, how voices are chosen, retries and failure mapping, what has and has not been verified, and how to run the tests. It describes the code in this repository; paths start at the repository root. For the whole spoken-call design (browser capture, the call state machine, playback) read [voice-architecture.md](voice-architecture.md), and for privacy [privacy-audio.md](privacy-audio.md).

**Nothing on this page has been checked against live Azure AI Speech.** The [verification table](#verification-status) says what was checked against a local fake server, what was checked against Microsoft's documentation, and what was not checked at all. The status of each provider kind is below.

| Provider kind  | Setting                                  | Tested with                                                                                   | Live check                    |
| -------------- | ---------------------------------------- | --------------------------------------------------------------------------------------------- | ----------------------------- |
| `none`         | `FIREFLY_SPEECH_PROVIDER=none` (default) | Unit, API and browser tests: the speech endpoints answer `speech_unavailable`.                | Not run (no external service) |
| `mock`         | `FIREFLY_SPEECH_PROVIDER=mock`           | Unit, API and browser tests, with a fake microphone.                                          | Not run (no external service) |
| `azure-speech` | `FIREFLY_SPEECH_PROVIDER=azure-speech`   | A local fake Azure speech server (`server/speech/fake-azure-speech-server.ts`) in unit tests. | Not run                       |

Azure AI Speech has not been run live. CI uses the fake server and the mock.

Code map: `server/speech/` (`types.ts` the two speech ports, configuration and errors; `service.ts` the use cases the routes call; `voices.ts` the voice catalogue, moods and SSML; `wav.ts` recording check; `mock.ts`; `azure.ts`; `index.ts` the factory; `direction.ts` speaker and mood), `shared/domain/voices.ts` (the four neutral voices) and `shared/domain/spoken-text.ts` (the sanitiser for spoken lines), `server/speech/fake-azure-speech-server.ts` (tests only), `server/http/app.ts` and `security.ts` (endpoints, limits, headers), `server/hooks.ts` (test failures), `server/services/sessions.ts` (`getSpeakableTurn`, error mapping), `server/db/database.ts` (migration 2, which adds `turns.input_mode`).

`GET /api/config` returns `speech: {provider, label, demo, transcribe, synthesize, expressiveStyles, notice, voices, limits}`. `voices` lists the four neutral choices (`id`, `label`, `trait`, `description`, and for each language whether the choice has a synthetic voice of its own (`own`) or shares one (`shared`) and whether mood can be performed with a style). It is empty when the provider cannot speak, and absent from a server that predates voice choice. `notice` is null unless a setting was wrong (see [Environment variables](#environment-variables)). Firefly never falls back from one provider to another while running: a failing Azure call is reported as an error and is never answered by the mock.

## Environment variables

Values written as `<...>` (the placeholders in `.env.example`) count as not set. Settings are read once at start-up, from the process environment, with `.env` filling in anything not already set. A wrong setting never stops the server: speech is turned off (or the one option ignored), `speech.notice` says which variable is wrong, and the start-up banner prints the same text. Notices name variables and never repeat values.

| Variable                                               | Default                                                                      | Allowed                                                                                                                                                                                | When wrong                                                                                                                                         |
| ------------------------------------------------------ | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |

Address rules for `AZURE_SPEECH_ENDPOINT`: a regional speech host (`<region>.stt.speech.microsoft.com` or `.tts.`, also `.azure.us` and `.azure.cn`) gets its matching speech-to-text and text-to-speech hosts with the regional paths (`/speech/recognition/conversation/cognitiveservices/v1`, `/cognitiveservices/v1`). Any other https host is treated as a custom domain: `<address>/stt/speech/recognition/conversation/cognitiveservices/v1` and `<address>/tts/cognitiveservices/v1`; a path prefix is kept and trailing slashes are removed. Not configurable: the audio format, the number of retries (one) and the limits in [Endpoints](#endpoints).

## Endpoints

Common to all three: POST only (any other method answers 405 `bad_request`); same-origin only (a mismatching `Origin` header answers 403 `forbidden`); identified by the `firefly_profile` cookie. Errors are `{"error":{"code","message","retryable","details"?}}`. Rate limit: bucket `speech`, capacity 60, refill 1 per second, per profile, shared by all three endpoints and taken before anything is read; the general `api` bucket (240, 4 per second) also applies. Because a caller that drops its cookie gets a fresh per-profile allowance every time, every speech request also takes from one server-wide bucket, `speech-all` (capacity 120, refill 4 per second), which bounds how much a metered speech service can be used however many profiles ask. An empty bucket answers 429 `rate_limited`, `retryable: true`, `details.retryAfterSeconds`. Firefly has no sign-in, so these limits are politeness and a cap on cost, not access control: keep it on a trusted network.

### POST /api/speech/transcribe?lang=en-GB

- Query: `lang` is `en-GB` (default), `en-US`, `en-IE`, `en-AU` or `en-IN`; anything else is 400 `validation_failed`.
- Body: the recording itself (not JSON). `Content-Type` `audio/wav` or `audio/x-wav` (capitals and parameters allowed). At most 1,500,000 bytes. A PCM WAV, mono, 16,000 Hz, 16-bit, at most 30 seconds. Extra chunks and the RIFF size field are ignored. Firefly forwards a re-written copy with a plain 44-byte header.
- Success 200: `{"status":"recognised"|"no-speech","text":string,"durationMs":number}`. `durationMs` is the length of the recording from its header. `text` is `""` for `no-speech`.
- Order of checks: rate limit, `lang`, speech turned on (503), content type (415), declared size (413), size while reading (413), recording (400), provider.
- 400 `validation_failed` messages for the recording: "That recording is not a WAV file."; "The recording has a damaged header."; "The recording has no format header."; "The recording must be 16-bit mono WAV at 16 kHz."; "The recording is empty."; "The recording looks incomplete."; "The recording looks damaged."; "The recording is longer than 30 seconds."
- Other errors: 413 `payload_too_large` "That recording is too large."; 415 `unsupported_media` "Send the recording as audio/wav."; provider errors as in [Timeouts, retries and failure mapping](#timeouts-retries-and-failure-mapping).

### POST /api/sessions/:id/turns/:index/speech?lang=en-GB&voice=voice-a

- Path: `:id` is the caller's own session; `:index` is the turn number from 1 (the opening is 1; customer turns are odd). Query: `lang` as above, and `voice`, optional, one of `voice-a`, `voice-b`, `voice-c` or `voice-d` (anything else is 400 `validation_failed`). With no `voice`, the older pairing by the persona's speaker is used, so a call saved before voices could be chosen sounds as it did. Body: ignored and not read; a declared body over 64 KiB is 413 `payload_too_large`. Works on ended calls.
- The words, the speaker and the mood (including whether the customer is cooling down) come from the stored call and cannot be supplied by the request (see [Voice selection](#voice-selection-and-mood-direction)).
- Success 200: the audio bytes. Headers: `Content-Type` (`audio/mpeg` for Azure, `audio/wav` for the mock), `Content-Length`, `Cache-Control: no-store`, `x-firefly-speech-provider` (`azure-speech` or `mock`), `x-firefly-speech-voice` (the voice name, `mock` for the demo), `x-firefly-speech-style` (the style requested for that voice, or `none`), `x-firefly-speech-voice-id` (the neutral voice the audio was made for, or `none` when none was asked for). These four headers appear on no other response except the preview's.
- Order of checks: rate limit, body size, `lang` and `voice`, session and turn, speech turned on (503), provider.
- Errors: 400 `validation_failed` (`lang` or `voice`); 400 `bad_request` "Only the customer's turns can be spoken." (a trainee turn); 404 `not_found` "That session was not found." (absent or another profile's) or "That turn was not found." (absent, or not a whole number of 1 to 5 digits); 413; provider errors as in [Timeouts, retries and failure mapping](#timeouts-retries-and-failure-mapping).

### POST /api/speech/preview?lang=en-GB&voice=voice-a

"Test voice" on the call brief. It speaks one fixed sentence, "Hello, this is a test of the voice you chose." (`VOICE_PREVIEW_TEXT` in `shared/domain/voices.ts`), in the chosen voice at a calm delivery. The sentence is fixed on the server, so the endpoint cannot be used to speak anything else. It needs no call and no body (a body is not read; over 64 KiB is 413). `voice` is required. Success and error responses are those of the turn endpoint, with the same four headers. It takes from the same `speech` and `speech-all` buckets as every other speech request.

Related: `GET /api/health` includes `speech: {kind}`. `limits` in `/api/config`: `maxAudioBytes` 1,500,000, `maxAudioSeconds` 30, `sampleRate` 16000. The content security policy has `media-src 'self' blob:` and `Permissions-Policy` keeps `microphone=(self)`.

## What is sent, stored and logged

Sent to Azure (azure-speech only), over https, with these headers and no others of substance (Node's `fetch` adds `accept-encoding`, `accept-language`, `connection`, `content-length`, `host`, `sec-fetch-mode`): `Ocp-Apim-Subscription-Key`, `User-Agent: Firefly`, `Content-Type`, `Accept: application/json` (speech to text) or `X-Microsoft-OutputFormat` (text to speech). No cookie, `Origin`, `Referer` or `Authorization` header is sent (checked against the fake's recorded headers).

- Speech to text: the trainee's recording (up to 30 seconds, 16 kHz mono PCM, header re-written, other chunks dropped), and the query `language`, `format=simple`, `profanity=raw`. `profanity=raw` keeps profanity as spoken because the report quotes the transcript as evidence; the service default is `masked` and `removed` would delete it. No pronunciation assessment, scores or anything about how the trainee sounds is requested.
- Text to speech: one SSML document holding the voice name, the language, optionally a style and its degree, rate and pitch values, and one customer line (control characters removed, at most 1,200 characters, XML-escaped).
- Not sent: the profile cookie or id, the session id, the scenario id or title, the persona's name, role, organisation, background or `voice` description, hidden facts, evaluator notes, success criteria, curveballs, engine numbers (temperature, trust, patience), classifications, scores, the report, the rest of the transcript, the trainee's typed text, and the API key anywhere but the header. By construction a provider is handed only the recording, its language and its length (`TranscribeRequest`), or the line and the voice direction (speaker hint, language, mood band, pace, intensity, the chosen neutral voice and whether the customer is cooling down) (`SynthesizeRequest`), both in `server/speech/types.ts`. A test ("sends Azure nothing about the profile, the session or the scenario beyond the customer line itself", `server/http/speech.test.ts`) checks the path, query, headers and SSML of both calls for the profile id, session id, scenario id and title, the persona's name, role, organisation, background and `voice` description, the evaluator notes, the customer's objective, the hidden facts and the success criteria of one scenario. The one scenario-derived text sent is the customer line being spoken, which the trainee already sees in the transcript; it contains a hidden fact only if the customer has already said it, and it can contain the fictional customer's name or organisation if they said it.
- Disclosed by the request itself: the style name and the rate and pitch values show the customer's mood band to the service in coarse terms. The recording can contain anything the trainee says aloud; Firefly cannot remove personal data from audio. Redaction of email, phone, card and identifier patterns (`redactSensitive`) runs on text when a message is sent, after recognition.

Stored by Firefly: no audio. Recordings are read into memory for one request, checked, re-written, sent on and dropped; spoken audio is held in memory, returned with `Cache-Control: no-store` and dropped. No code in `server/speech/`, `app.ts` or `security.ts` imports `node:fs` (checked with a search of `server/`). The text spoken is read from the stored call. Recognised text is returned to the browser and is stored only if the browser sends it as a message, as the trainee turn with `input_mode` `voice` (migration 2; `text` for typed turns, customer turns and the opening).

Logged: one JSON line on standard output per event, with `time`, `level`, `event`. Fields named `text`, `body`, `transcript`, `apiKey`, `api_key`, `authorization`, `password`, `secret`, `token` or `prompt` are dropped and strings over 200 characters are cut (`server/log.ts`).

| Event (level)                                            | Fields                                                                                                                                                                                                                                                                                                                                     |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `request` (info), every API request                      | `requestId` (8 hex characters), `route` (for example `POST /api/sessions/:id/turns/:id/speech`, or `unmatched` when the request fails before a route matches: the raw path is never logged), `status` (499 for a request the browser cancelled, such as an abandoned upload), `ms`, and `sessionId` (first 8 characters) on session routes |
| `speech.transcribed` (info)                              | `requestId`, `provider`, `bytes` (upload size), `audioMs`, `status` (`recognised` or `no-speech`), `ms`                                                                                                                                                                                                                                    |
| `speech.spoken` (info)                                   | `requestId`, `provider`, `bytes` (audio size), `ms`                                                                                                                                                                                                                                                                                        |
| `speech.previewed` (info)                                | `requestId`, `provider`, `voice` (the neutral choice, such as `voice-a`), `bytes`, `ms`                                                                                                                                                                                                                                                    |
| `speech.failed` (warn), not for a client that went away  | `requestId`, `op` (`transcribe`, `speak` or `preview`), `provider`, `code`, `ms`                                                                                                                                                                                                                                                           |
| `request.error` (error), unexpected internal errors only | `requestId`, `error` (first 200 characters of the message)                                                                                                                                                                                                                                                                                 |

Never logged: audio, recognised or spoken words, the key, the provider's own wording, addresses, headers. Tests: `server/http/speech.test.ts`, "what the server logs about speech".

Microsoft's own statements (checked on 21 November 2026, see [Documentation checked](#documentation-checked)): for real-time speech to text, audio is processed in server memory and no data is stored at rest; for real-time synthesis with a prebuilt neural voice, neither the input text nor the output audio is stored in Microsoft logs. Firefly does not inspect the operator's resource settings.

## Voice selection and mood direction

**The four choices.** The trainee picks one of four neutral voices, Voice A to Voice D (`shared/domain/voices.ts`), and the speech request names it with `voice=`. The server maps each choice to one Azure voice per language (`VOICE_CATALOGUE` in `server/speech/voices.ts`):

| Language | Voice A               | Voice B               | Voice C                       | Voice D                      |
| -------- | --------------------- | --------------------- | ----------------------------- | ---------------------------- |
| en-GB    | `en-GB-SoniaNeural`   | `en-GB-RyanNeural`    | `en-GB-LibbyNeural`           | `en-GB-ThomasNeural`         |
| en-US    | `en-US-GuyNeural`     | `en-US-AriaNeural`    | `en-US-DavisNeural`           | `en-US-JennyNeural`          |
| en-IE    | `en-IE-ConnorNeural`  | `en-IE-EmilyNeural`   | `en-IE-ConnorNeural` (shared) | `en-IE-EmilyNeural` (shared) |
| en-AU    | `en-AU-NatashaNeural` | `en-AU-WilliamNeural` | `en-AU-DarrenNeural`          | `en-AU-AnnetteNeural`        |
| en-IN    | `en-IN-AaravNeural`   | `en-IN-NeerjaNeural`  | `en-IN-AashiNeural`           | `en-IN-KunalNeural`          |

Where Azure has fewer than four standard voices in a language (Ireland has two), a choice shares an earlier choice's voice and differs by pace alone, and `GET /api/config` says so. Each choice adds its own pace to the rate: Voice A -2%, B +4%, C -6% and D +2%. Every voice name comes from the voice table on Microsoft's language support page, as recorded in the code comment dated 18 November 2026. That page was not re-read for this document, and no voice has been heard or called live. `AZURE_SPEECH_VOICE_FEMALE` and `AZURE_SPEECH_VOICE_MALE` never replace a voice the trainee chose.

**The older pairing.** With no `voice`, the speaker is `persona.speaker` (`female` or `male`) from the scenario; it is never sent to the browser. A call stored before that field existed gets a speaker derived from a hash of the lowercased persona name, so the voice stays the same for the whole call. That is the pairing for calls saved before voices could be chosen, and for clients that name no voice.

**The mood** is the customer's temperature band at that turn: the starting temperature plus every stored temperature change caused by earlier trainee turns (`temperatureAtTurn`). A customer who is cooling down (their temperature fell with the latest change and now stands at least 8 points below where it stood before any of the last three changes) gets no style, half the rate increase if it was above zero and then 3% lower, and half the pitch change (`recoveringAtTurn`).

The older pairing, with the voices' styles (a voice must list a style for it to be used; styles are copied from the voice table of "Language and Voice Support for Azure Speech"):

| Language | Female                | Male                  | Styles listed                                                |
| -------- | --------------------- | --------------------- | ------------------------------------------------------------ |
| en-GB    | `en-GB-SoniaNeural`   | `en-GB-RyanNeural`    | Sonia: cheerful, sad. Ryan: chat, cheerful, sad, whispering  |
| en-US    | `en-US-AriaNeural`    | `en-US-GuyNeural`     | Both list `angry` and `unfriendly` (Aria 16 styles, Guy 11)  |
| en-IE    | `en-IE-EmilyNeural`   | `en-IE-ConnorNeural`  | None listed                                                  |
| en-AU    | `en-AU-NatashaNeural` | `en-AU-WilliamNeural` | None listed                                                  |
| en-IN    | `en-IN-NeerjaNeural`  | `en-IN-PrabhatNeural` | Neerja: cheerful, empathetic, newscast. Prabhat: none listed |

`VOICE_STYLES` also holds the voices the four choices use. Of those, only the en-US ones (Guy, Aria, Davis and Jenny) list `angry` and `unfriendly`. Libby, Thomas, Darren, Annette, Aarav, Aashi and Kunal list no styles, and Neerja lists cheerful, empathetic and newscast. `en-US-JaneNeural`, `-JasonNeural` and `-SaraNeural` are in the table for operators who replace the pairing (all list `angry` and `unfriendly`). A voice that is not in the table never gets a style. `shouting` is never requested. The SSML `xml:lang` is the voice's own locale.

| Mood band  | Pace, intensity | Style (only if the voice lists it) | Rate | Pitch (only when no style is applied) |
| ---------- | --------------- | ---------------------------------- | ---- | ------------------------------------- |
| calm       | measured, 0     | none                               | -4%  | none                                  |
| concerned  | brisk, 0.25     | none                               | +6%  | +3%                                   |
| frustrated | firm, 0.5       | `unfriendly`, degree 0.55          | +8%  | -2%                                   |
| angry      | firm, 0.75      | `angry`, degree 0.73               | +11% | -3%                                   |
| escalating | firm, 1         | `angry`, degree 0.9                | +14% | -4%                                   |

Degree is `min(0.9, 0.20 + 0.70 x intensity)`, always below the style's default of 1. The rate and pitch numbers are Firefly's own conservative choices and were not tuned by listening. A line over 1,200 characters is spoken up to the last whole sentence that fits (else the last whole word); the stored transcript is not changed.

Honest statement. The voice is synthetic. Firefly changes its pace and pitch and, only for the few voices whose documentation lists a matching style, asks for that style at a reduced degree. Neither the service nor Firefly measures or guarantees that the result sounds like the stated emotion, and the interface must not claim that it does. The `x-firefly-speech-style` and `x-firefly-speech-voice` headers report what Firefly requested; Azure does not say what it applied, so a style the service ignored cannot be detected. `expressiveStyles` in `/api/config` is true only when every language and both speakers of the older pairing resolve to voices that list both `unfriendly` and `angry`: false with the built-in voices. Firefly never infers emotion from the trainee's voice.

## Timeouts, retries and failure mapping

Each attempt to Azure has its own timeout (`FIREFLY_SPEECH_TIMEOUT_MS`). An attempt that fails with HTTP 429, HTTP 500 or above, or a network error is tried once more after 300 ms, or after `Retry-After` capped at 2 seconds. Never retried: a timeout, any other HTTP error, `RecognitionStatus` `Error`, an unusable answer. A call can therefore last up to twice the timeout plus 2 seconds. Redirects are never followed, so the key cannot be sent to another host. A caller that disconnects cancels the Azure call and nothing is returned. The messages are fixed sentences (`SPEECH_MESSAGES`, `SPEECH_OFF_MESSAGES`); the interface decides how to show them.

| Situation                                                                                                                                         | Status, code, retryable         | Message sent                                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Speech off (transcribe / speak)                                                                                                                   | 503 `speech_unavailable`, false | "Speech is not turned on for this server, so type your reply instead." / "The customer's voice is not turned on for this server, so read their reply instead." |
| Azure 401, 403, 404, or a redirect                                                                                                                | 503 `speech_unavailable`, false | "Speech is not configured correctly on this server, so spoken calls are unavailable. Ask whoever runs Firefly to check the speech settings."                   |
| Azure 429 twice                                                                                                                                   | 429 `speech_rate_limited`, true | "The speech service is busy right now. Please try again in a moment."                                                                                          |
| Timeout, or Azure 408                                                                                                                             | 504 `speech_timeout`, true      | "The speech service took too long to respond. Please try again."                                                                                               |
| Azure 500 or above twice; `RecognitionStatus` `Error`                                                                                             | 502 `speech_failed`, true       | "The speech service could not complete that request. Please try again."                                                                                        |
| Network error twice                                                                                                                               | 502 `speech_failed`, true       | "Could not reach the speech service. Please try again in a moment."                                                                                            |
| Azure 400, 415, 422 and other 4xx                                                                                                                 | 502 `speech_failed`, false      | "The speech service did not accept that request."                                                                                                              |
| Answer not usable: bad JSON, unknown status, audio that starts like JSON, XML or HTML, under 32 bytes, over 8 MiB, recognition answer over 64 KiB | 502 `speech_failed`, true       | "The speech service returned something Firefly could not use. Please try again."                                                                               |
| Line with nothing to speak                                                                                                                        | 502 `speech_failed`, false      | "There is nothing to speak in that line."                                                                                                                      |
| `NoMatch`, `InitialSilenceTimeout`, `BabbleTimeout`, or empty text                                                                                | 200 `no-speech`                 | none                                                                                                                                                           |

Never in a message or an error: the key, the address, the provider's wording, audio, or any line of the call (tests: `expectNoLeak` in `azure.test.ts`, and the HTTP tests).

## Running the speech tests and the fake server

- Whole server suite: `cmd /c "npx vitest run --project server"` (in other shells, `npx vitest run --project server`). Speech only: add the paths `server/speech server/http server/db server/hooks`. Also `npx eslint server shared`, `npx prettier --check server shared`, `node scripts/scan-secrets.mjs`. No test calls a real service.
- The fake, `server/speech/fake-azure-speech-server.ts`: `const fake = await startFakeAzureSpeech({ key?, recognisedText? })` listens on 127.0.0.1 and returns `{ origin, key, sttUrl, ttsUrl, customBase, requests, enqueue, respondWith, reset, close }`. It answers both services in the regional and custom-domain layouts, checks the key, content types, `language`, `format`, `profanity`, output format, `User-Agent` and SSML shape as the service documents, records every request (`query`, `search`, `headers`, `body`, `text`), and answers from a script: `enqueue(...)` takes steps such as `{ recognition: 'Success'|'NoMatch'|..., text }`, `{ audio: true }` or `{ status, json|text|body, headers }`, which accept an optional `delayMs`, and `{ drop: true }` or `{ hang: true }`, which do not; `respondWith(fn)` answers dynamically. Unscripted valid requests succeed. For recognition it stands in for the `profanity` option: `masked` (also when the option is absent) turns the mild words damn, bloody and crap into their first letter and asterisks, `removed` deletes them, `raw` keeps them, and any other value is 400. This shows that Firefly asks for `raw`; it is not the real service's word list or masking format (see [Verification status](#verification-status)).
- Use it by building the provider directly, because `AZURE_SPEECH_ENDPOINT` must be https: `createAzureSpeechProvider({ kind: 'azure-speech', apiKey: fake.key, sttUrl: fake.sttUrl, ttsUrl: fake.ttsUrl, voices: { female: null, male: null }, timeoutMs: 1000 }, { sleep: () => Promise.resolve() })`, then `createTestApp({ speech })` from `server/http/harness.ts` (options `speech`, `log`, `testHooks`).
- Running the whole product without Azure: `FIREFLY_SPEECH_PROVIDER=mock FIREFLY_TEST_HOOKS=1`. Then `POST /api/test/fail-next` with `{"target":"transcribe"|"synthesize","count":1}` (count 0 to 5) makes the next such calls fail with 502 `speech_failed`, "The speech service is temporarily unavailable (simulated failure).", retryable. The targets `customer`, `classifier` and `evaluator` take the same body but fail model calls, with `provider_unavailable`. A queued failure is used up only by a request that reaches the provider, so a request refused earlier (bad `lang`, bad recording, speech off) does not consume it.

## Managed identity and Key Vault

Implemented: Firefly reads the key from the environment variable `AZURE_SPEECH_KEY` only (the environment, then `.env`) and sends it as `Ocp-Apim-Subscription-Key`. It does not read Key Vault, call `issueToken` or use any token.

NOT IMPLEMENTED: documentation of a path an operator could use. The operator would store the key as a Key Vault secret and let the hosting platform place it in the environment of the Firefly process before it starts. On Azure App Service, an app setting named `AZURE_SPEECH_KEY` can hold a Key Vault reference, `@Microsoft.KeyVault(SecretUri=https://<vault>.vault.azure.net/secrets/<name>)`, resolved by a managed identity that has the Key Vault Secrets User role (or the Get secrets permission); without a version the latest version is used and refreshed within 24 hours (page: "Use Key Vault References as App Settings - Azure App Service"). On Azure Container Apps, a secret can be a Key Vault reference using a managed identity with the Key Vault Secrets User role, and an environment variable can take its value from it (`secretref:`); without a version the latest is fetched within 30 minutes and active revisions that use it restart (page: "Manage secrets in Azure Container Apps"). Firefly needs no change for either, because it only sees an ordinary environment variable. Both paths still put the key value in the process environment.

NOT IMPLEMENTED: Microsoft Entra ID token authentication to the speech endpoint. The short-audio and text-to-speech REST pages describe a bearer value of the form `aad#<resource id>#<Entra token>`; "How to configure Microsoft Entra authentication - Foundry Tools" says the resource needs a custom domain and the caller needs the Cognitive Services Speech User or Speech Contributor role. Firefly sends none of this and has no tests for it; supporting it would need an endpoint with a custom domain, a token source and a refresh rule.
