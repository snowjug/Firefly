# Design system

Firefly's interface is built on one small design system, written for this project. It is informed by Microsoft's public Fluent 2 web light theme (colour values and type ramp checked against Microsoft's open-source Fluent UI tokens) but it is an original implementation: Fluent UI React is not used, no Microsoft asset is copied, and the logo mark is Firefly's own. The interface is **light only**, by decision. It uses the system's Segoe UI Variable where it exists, and system fonts elsewhere; no web font is downloaded.

Where it lives:

| Path                                  | Contents                                                                                                                                |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `web/src/design/tokens.css`           | Every colour, type, spacing, radius, shadow, motion and focus value, as CSS custom properties.                                          |
| `web/src/design/base.css`, `type.css` | The reset, focus, shared entrances, reduced-motion, contrast and forced-colours rules, and the type roles (`t-*`).                      |
| `web/src/design/layout.css`           | Page and layout helpers (`l-*`) and small utilities (`u-*`).                                                                            |
| `web/src/design/primitives/`          | One component and one stylesheet each. Imported through `web/src/design/index.ts`.                                                      |
| `web/src/design/icons.tsx`            | 70 hand-drawn inline SVG icons (`Icon`, `ICON_NAMES`). No icon font or icon library. Product marks are separate (`ProductIcon`).        |
| `web/src/app/`                        | The shell: router, layouts, headers, footer, wordmark, route errors, skip link, offline notice, scroll and focus handling.              |
| `web/gallery.html`                    | A development-only page that shows every primitive in every state, with a replay for each movement. Served by the Vite dev server only. |

## Direction (the brief for every screen)

| Question         | Answer                                                                                                                                                                                               |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Purpose          | A new Microsoft support engineer practises a customer call by voice and learns from coaching grounded in the transcript.                                                                             |
| Audience         | Apprentices and new hires, on a corporate Windows laptop, repeating the same flow: scan, choose, speak, review. They need status at a glance and almost no reading.                                  |
| Tone             | Microsoft 365 and Dynamics: calm, compact but breathable, one blue for actions and selection, neutral everything else, subtle elevation, clear commands and clear status. Icons with concise labels. |
| Memorable detail | The product shows itself: the landing page's hero is a working call moment built from the real components (state, waveform, words, score), and every movement exists to explain a state.             |
| Constraints      | Fluent 2 principles, system fonts, a strict CSP (no inline styles in markup), bundle budgets (`scripts/budgets.json`), WCAG 2.2 AA, light mode, no dependency added.                                 |
| Target viewports | 320, 375, 430, 768, 1024, 1440 and 1920 px wide; text at 200 per cent; reduced motion; forced colours.                                                                                               |
| Never            | Glass, neon, decorative gradients, 3D, particles, a cosmic metaphor, gamification, paragraphs that explain what a control already says, card grids as a layout habit.                                |

Slop check (generic AI-made design patterns): no gratuitous gradients (the only gradients are the sweep of a shimmer and the stripes that replace it under reduced motion); no purple-to-blue defaults (the indigo `--ai-*` accent marks the provider and nothing else); **glass removed** (the sticky header was 78 per cent white with a 20 px backdrop blur: now a solid surface with a hairline, which also costs nothing to paint); radii follow one scale (4 controls, 8 panels, 12 dialogs); no motion on scroll; the hero is left-aligned beside a real preview, not centred text over a gradient; the font is the system's, deliberately.

## Principles

- **Calm and legible.** White canvas, restrained neutrals, one brand colour for actions, selection and active state. Nothing decorative moves.
- **Little text.** A label, an icon or the layout says it first; detail is folded behind a disclosure. Landing and content pages have copy budgets that tests count from the rendered DOM.
- **Colour never carries meaning alone.** Customer mood, scores, status and found/missed facts always have a word, and mood has a distinct icon shape for each of its six states.
- **Native first.** Native `<dialog>`, `<select>`, radio groups and checkboxes where they do the job, with roving tabindex only where a pattern needs it (tabs).
- **Targets are large.** Primary controls are 44 px high, dense controls 32 px, and nothing is below 24 px.
- **Motion explains, then stops.** Short, interruptible transitions; only `transform` and `opacity` move; every movement has a still equivalent under `prefers-reduced-motion`; nothing repeats for more than a few seconds unless it is the state itself.
- **Text is plain.** Anything from a user or a model is rendered as text, never as HTML.

## Tokens

Components use semantic tokens (`--fg-*`, `--bg-*`, `--brand*`, `--state-*`, `--status-*`) and never raw colour values.

| Group          | Tokens                                                                                                                                                                                                                                                         |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Type           | `--font-base`, `--font-display`, `--font-mono`; scale from caption (12/16) through body (14/20), reading (16/24), lead (18/28), subtitle, title 3 to 1 and a fluid display size (30 to 40 px).                                                                 |
| Neutrals       | `--bg-canvas` `#ffffff`, `--bg-quiet`, `--bg-subtle`, `--bg-section`, `--bg-strong`; text `--fg-1`, `--fg-2`, `--fg-3` (`#616161`, the lightest text used), `--fg-disabled`.                                                                                   |
| Brand          | `--brand` `#0f6cbd`, hover `#115ea3`, pressed `#0c3b5e`, tint `#ebf3fc`, link `#115ea3`.                                                                                                                                                                       |
| Status         | `--status-{success,warning,danger,info,neutral}-{fg,bg,border}`.                                                                                                                                                                                               |
| Customer mood  | `--state-{calm,concerned,frustrated,angry,escalating,recovering}-{fg,bg,border}`. Always shown with a label and its own icon.                                                                                                                                  |
| Accents        | `--ai-*` (analysis written by the coaching evaluator, used sparingly), `--voice-trainee` and `--voice-customer` (waveforms).                                                                                                                                   |
| Spacing, shape | A 4 px grid (`--sp-*`), radii, three shadow levels, and `--acrylic-*`, which now resolve to a solid surface (the names stay so nothing breaks).                                                                                                                |
| Control sizes  | `--ctl-sm` 32, `--ctl-md` 44, `--ctl-lg` 48.                                                                                                                                                                                                                   |
| Motion         | Durations `--dur-instant` 50 ms to `--dur-slower` 400 ms; repeating motion `--dur-spin`, `--dur-slide`, `--dur-shimmer`, `--dur-pulse`, `--dur-wave`; travel `--move-xs`, `--move-sm`; press `--press-shift` 1 px, `--press-shift-lg` 2 px; curves `--ease-*`. |
| Focus          | A 2 px black outline with a 1 px white inner ring (21:1 on white), on every focusable element. In forced-colours mode the system colours are used instead.                                                                                                     |

Breakpoints cannot be custom properties, so they are written as media queries: 30em (480), 40em (640), 48em (768), 64em (1024), 80em (1280), 90em (1440) and 120em (1920).

## Motion

One rule set, enforced by `design/motion.test.ts` and `design/tokens.test.ts` on the design system, the shell and the public pages:

1. **Only `transform` and `opacity` move.** A transition may also change colour, border colour or shadow for hover, press and selection (paint only); never a layout property, never `all`. A keyframe moves `transform` and `opacity` only. (Why: a width, inset or margin that animates moves the page under the person's hands.)
2. **Every time comes from a token.** No stylesheet writes `200ms`. Each `--dur-*`, `--move-*` and `--press-*` token has a still equivalent in the reduced-motion block of `tokens.css` (durations 0.01 ms, distances 0), and a test fails if one is added without it. `base.css` ends every animation and transition under `prefers-reduced-motion: reduce` as a floor.
3. **Movement explains state.** The press compresses a button 1 px (2 px for the large one); a main action's arrow leans on hover and focus; a new row or panel rises a few pixels as it fades in (`u-enter`, `u-fade`); a status word fades in place; a score fills once, from empty, when motion is allowed; tab panels crossfade in one cell, so nothing below them moves.
4. **Nothing repeats for long.** The landing page's waveform swings three times (about 3.5 s) and rests, and replays when a product tab is chosen, so the page needs no pause control (WCAG 2.2.2). The only endless motion is the state itself (a spinner, a listening pulse), still under reduced motion.

## Shell and routing

`web/src/app/router.tsx` builds a React Router data router with three layouts: **public** (`/`, `/responsible-ai`, `/about`, the not-found page), **app** (`/scenarios`, `/scenarios/:id/brief`, `/sessions/:id/report`) and **call** (`/calls/:id`, which has no navigation, only a skip link and `main`, so the call has the whole screen).

- The public header is the wordmark, **Scenarios**, **Responsible AI** and the main action **Start call**; below 48em the two links fold into a disclosure menu and the action stays in the bar. The app header names the section, shows the provider status (always "Demo mode" when it is, never a guess when the config did not load) and offers a way back. The footer is one line and three links.
- Every page is a lazy route and a default export. Titles go through `useDocumentTitle`; the page's place in the app header goes through `useAppSection`.
- After a client navigation, focus moves to the section a `#hash` names, or to `main` for a new path. A query-only change and the first load never move focus.
- Each layout has its own error boundary, so a failing page keeps the header and footer around a short message (`ErrorMessage`: not found, did not load, something went wrong). It never shows the error's own text. A failed lazy chunk offers a reload.

## Class ownership

| Prefix        | Owner                                                                                                                                                       |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ff-*`        | The design system: one stylesheet per primitive (`design/primitives/*.css`) and per shell part (`app/shell/*.css`).                                         |
| `l-*`, `u-*`  | `layout.css`: `l-page`, `l-stack`, `l-cluster`, `l-grid`, `l-split`, gaps `l-gap-1` to `l-gap-12`; `u-nowrap`, `u-truncate`, `u-enter`, `u-fade` and so on. |
| `t-*`         | `type.css`.                                                                                                                                                 |
| Anything else | A feature's own short prefix (`lp-` and `cp-` for the landing page, `ct-` for content pages, `cw-` for the call workspace, `rp-` for the report).           |

A feature stylesheet must never be the subject of a rule on an `ff-*` class. Joined selectors (`.ff-button.cw-x`), descendants (`.cw-x .ff-button`) and `:has` scopes are allowed, and a test (`class-ownership.test.ts`) scans every stylesheet under `web/src` and fails otherwise.

## Contrast and accessibility

Contrast is measured from the tokens by a test (`tokens.test.ts`, which also covers the motion tokens), so a colour change that fails fails the build. The lowest text pair is 4.81:1.

| Pair                                                                                           | Ratio                        |
| ---------------------------------------------------------------------------------------------- | ---------------------------- |
| `--fg-1`, `--fg-2`, `--fg-3` on white                                                          | 15.5, 10.1, 6.2              |
| White on brand, brand hover, danger                                                            | 5.4, 6.7, 7.1                |
| Status foreground on its background (success, warning, danger, info, neutral)                  | 5.9, 4.9, 6.6, 4.8, 9.2      |
| Mood foreground on its background (calm, concerned, frustrated, angry, escalating, recovering) | 5.9, 5.9, 5.1, 6.6, 9.9, 5.9 |
| Accessible control edge on white                                                               | 6.2                          |
| Focus ring on white                                                                            | 21                           |

Measured on the rebuilt pages in Edge with axe (WCAG 2.0 to 2.2 A and AA, and best practice): 0 violations on the landing, Responsible AI, About and not-found pages at 375 and 1440 px. Not tested: a screen reader (Narrator or NVDA), touch hardware, and any browser but Edge. The wider list of what was checked, and what was not, is in [accessibility.md](accessibility.md).

## Changing the system

1. Use an existing token or primitive. If none fits, add it to `web/src/design` with its own stylesheet, a gallery entry and a test, rather than styling it inside a page.
2. Keep names additive: do not rename or remove an export, a prop, a class or a token that a page uses. Change values instead.
3. Take every time and distance from the motion tokens and give each new one its reduced-motion value; `motion.test.ts` and `tokens.test.ts` fail otherwise.
4. Run `npm run dev` and open `/gallery.html` to see every state, then check the result at 320 px and 1440 px, with the keyboard only, with reduced motion and with forced colours.
5. A new dependency needs a reason in the commit message. The browser bundle contains React, React Router and Firefly's own code. `zod` is a server-side dependency and stays out of the browser bundle: the web app imports only types and plain constants from `shared/`.
