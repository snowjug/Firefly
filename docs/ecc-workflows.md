# ECC workflows

Firefly's rebuild into a voice-first Microsoft support call simulator, and the interface and interaction rebuild that followed it, used a set of reusable agent skills from [ECC](https://github.com/affaan-m/ECC). This page records which skills were chosen, how they were brought in, what was not installed, and where each one changed the work. It is a provenance record, not a product feature: nothing here runs in the app.

## How the skills were chosen

1. ECC's README, `AGENTS.md` and install scripts were read to learn how skills are installed and where GitHub Copilot CLI looks for them (`.github/skills/` is one of its project locations).
2. All 328 skill names were listed and 57 plausible candidates had their `SKILL.md` downloaded and examined.
3. 29 were selected because the work in this repository materially needs them. The other 28 were considered and left out (below). The whole catalogue was not installed.
4. For the second round (the interface and interaction rebuild) ECC's `main` was checked again: it was still at the commit above, with the same 328 skills. One more skill was selected, `motion-advanced`, for the gesture, loop and cleanup rules that the carousel, the tips and the landing preview needed. The 30 selected skills are the ones installed.

## How they were installed

ECC's managed installer (`install-apply.js --target copilot`) was run first as a dry run with the 29 skills of the first round named. It planned 474 operations (rules for every language, agents, commands and platform configuration), so it was **not** applied: that would install far more than was selected. (`npx ecc-universal` was also tried; it failed with `EALLOWREMOTE` because this npm setup refuses remote tarballs.)

Instead the 29 selected skill directories were copied unmodified from the pinned commit into `.github/skills/`, the documented manual route for Copilot CLI. In the second round `motion-advanced` was copied the same way (commit `8eb12b0`) and added to `.github/ecc/skills.lock.json`, which now lists 30 skills. Nothing else from ECC was installed: no hooks, rules, agents, commands or MCP configuration.

Check: `copilot skill list --json` reports all 30 with `"source": "project"` and `"enabled": true`, including `motion-advanced` (run again on 22 November 2026, from this repository's checkout). A session that was already running when the files appeared did not hot-load them, so in that session each procedure was applied by reading its `SKILL.md` and following it. Later sessions discover the skills directly.

The vendored files are third-party text kept as published, so Prettier and ESLint skip `.github/skills` and `.github/ecc` (see `.prettierignore` and `eslint.config.js`).

## Limits that were met

- `delivery-gate` is a Claude Code stop hook (Python and `~/.claude`). It cannot run under Copilot CLI, so its checks were applied by hand as the final checklist in the plan.
- `documentation-lookup` fetches documentation through a Context7 MCP server. None is configured here, so documentation was read from the vendors' own pages instead.
- No ECC skill covers visual regression, so screenshots were inspected by eye during `browser-qa` rather than compared automatically.
- `motion-foundations` is written for `motion/react`. Firefly uses CSS transitions, so only its rules were applied: motion must communicate state, animate only `transform` and `opacity`, take values from shared tokens, and fall back to short opacity changes under reduced motion.
- `motion-advanced` is also written for a motion library. Firefly has none (CSS and a few small hooks), so only its rules were applied, and the library's spring and gesture code was not used: a release is decided by the distance dragged and the speed together, never the speed alone (`web/src/design/interaction/use-drag-scroll.ts`); the thresholds are named constants; loops pause when their element is off screen or the tab is hidden; the hooks remove their listeners and cancel their frames and timers when they unmount. The one spring (`--ease-spring`) is a CSS easing, and `web/src/design/motion.test.ts` limits it to the folders that may use it.
- `react-testing` examples use MSW and TanStack Query. Firefly uses neither, so its query priority, `userEvent` and axe guidance were applied with the existing fakes.

## Security review

Applied from `security-review` to the server and speech code, by reading the code and searching it, not by a scanner:

- No `dangerouslySetInnerHTML`, `innerHTML` assignment, `eval` or `new Function` in the application source.
- Responses carry `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, a Content-Security-Policy, `frame-ancestors 'none'`, `Cross-Origin-Opener-Policy: same-origin` and a `Permissions-Policy` that allows the microphone for this origin only; API responses are `no-store` (`server/http/security.ts`).
- The anonymous profile cookie is `HttpOnly; SameSite=Lax`, and `Secure` when the request is secure. A write is refused when its `Origin` header (which browsers send on cross-site writes) is `null` or does not match the host; requests with no `Origin`, such as scripts, are not blocked by this check.
- Request bodies are size-limited (64 KB for JSON; a configured maximum for audio, refused from the `Content-Length` header before any bytes are read) and every body and query is parsed with a zod schema.
- Rate limits exist for general API use, session creation, messages, ending a call and speech, with a server-wide speech limit to bound provider cost.
- Audio is held in memory for one request, its bytes are zeroed afterwards, and it is never written to disk or logged. Speech log lines carry the provider, sizes, durations and error codes, never audio or words. The speech endpoints can only speak a stored customer turn or one fixed sentence, so they cannot be used as a general text-to-speech proxy.
- Guard failures from the model path are logged as codes only, never reply text.
- `npm run check:secrets` found nothing in the working tree. The only runtime dependencies are `react`, `react-dom`, `react-router` and `zod`.
- Not done: `npm audit` could not be run from this machine (the configured registry rate-limited the request and the public registry's TLS handshake failed), so the advisory audit job in CI is the only dependency check. There was no penetration test.
