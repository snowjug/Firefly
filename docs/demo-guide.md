# Demo guide

A runbook for showing Firefly to a team, a mentor or a panel in about 15 minutes. It says what to show, what to say and what not to claim. It describes what the repository does today. If you change the set-up, change the script. The times are a plan, not a measurement.

## Before you start

1. **Install and check.** You need Node.js 24 or later. Run `npm ci`, then `npm run check`. It runs the format check, lint, type check, scenario validation, tests, build, size budgets, secret scan and lockfile check. Fix anything that fails before the day.
2. **Pick a set-up and say which one you are using.** Put settings in `.env` (copy `.env.example`). Firefly reads `.env` when it starts, so restart after a change.

   | Set-up                         | Settings                                                                          | What the audience sees                                                                                                                                                                                                                                                                                                                                                                                        |
   | ------------------------------ | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | **Demo mode, typed**           | None. It is the default.                                                          | The whole product, with Firefly's rules engine as the customer. No credentials and no network. Start the call with **Start a text-only call**. This is the safest choice.                                                                                                                                                                                                                                     |
   | **Demo mode, scripted speech** | `FIREFLY_SPEECH_PROVIDER=mock`                                                    | A full spoken-call flow with a real microphone, labelled "Demo speech (scripted)". It does not understand audio. Whatever you say, the next of eight scripted engineer sentences appears as your line. The customer's "voice" is a soft sound and the reply appears as text.                                                                                                                                  |
   | **Browser speech**             | Leave `FIREFLY_SPEECH_PROVIDER` unset and use Edge or Chrome.                     | The browser's own recognition and voices. Try it on the demo machine first. Under automation, Edge and Chrome returned no words (a note in `e2e/perf.spec.ts`), and it has not been tested with real speech. Keep typing ready.                                                                                                                                                                               |
   | **Live model**                 | `FIREFLY_PROVIDER=gemini` and `GEMINI_API_KEY`                                    | A language model plays the customer and drafts the coaching. Rehearse it on the day and keep demo mode ready (see [ai-providers.md](ai-providers.md#status-of-each-provider)). |
   | **Live speech**                | `FIREFLY_SPEECH_PROVIDER=azure-speech`, `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION` | Azure AI Speech has not been run against the real service. Do not make this the demo.                                                                                                                                                                                                                                                                                                                         |

3. **Rehearse the scenario.** The script uses _Colleagues cannot join scheduled Teams meetings_: the customer is Priya Raman at Tailspin Toys, the call is a first contact, and the preset is Standard. Play it once so you know what the customer says. The wording changes from call to call. To show guided practice, also try _Shared team mailbox missing from Outlook_ (Starter), where Live hints are on by default and the case panel adds "Areas to explore".
4. **Reset after the rehearsal.** Restart the server. Scripted speech takes its sentences in order from one list for the whole server process, so a rehearsal moves the starting point. Delete the rehearsal calls (see [After the demo](#after-the-demo)), or set `FIREFLY_DB_PATH=:memory:` for a database that disappears when the server stops. The browser tests use that setting.
5. **Start the app.** For development, run `npm run dev` and open <http://localhost:5173>. For a production-style run, run `npm run build`, then `npm start`, and open <http://127.0.0.1:8787>.
6. **Check the room.** A quiet room and a headset help with voice. Allow the microphone for the address in advance if the browser remembered a "block". Keep the brief page open so you can switch to a text call at once.
7. **Close what you do not need.** Other tabs, notifications and anything else that uses the microphone.

In demo mode the customer's reply is delayed by 700 ms on purpose (`FIREFLY_MOCK_DELAY_MS`) so the typing state is visible. It says nothing about speed.

### What to expect in demo mode

The customer opens with a greeting only. After you greet them, they say why they called. They give a fact only to a question that fits it. A dismissive line raises the mood. If nobody has taken ownership, a request to speak to a manager can follow. Owning the problem with a time calms the customer. The words differ from call to call. See [customer-realism.md](customer-realism.md) for the rules.

In a spoken call, hands-free listening is on by default: the microphone opens by itself after each customer reply. With scripted speech, every recording that reaches the server (150 ms or more) uses up the next scripted sentence, whatever it holds. Keep the room quiet while the customer replies, or turn **Hands-free** off in **Settings** and press **Talk** for each turn. The microphone also stays live while the "End the call?" dialog is open, so press **Pause** before **End call**.

### Lines to type in demo mode

In a scripted run of this scenario in demo mode, with these lines, the customer gave the reason after the first line, gave up facts to the scoping questions, rose in mood after the dismissive line and eased after the recovery line. The rules engine matches patterns in words, so a line with unusual wording may not be recognised. Use them as a guide, not a script.

- **Greet:** "Hello, this is Sam from Microsoft support. How can I help you today?"
- **Empathise and open up:** "I'm sorry the meetings are failing, that sounds stressful with the presentation coming up. What exactly happens when someone tries to join?"
- **Scope:** "Who is affected, and does it happen with every meeting or only some?"
- **Ask about changes:** "Has anything changed recently, for example a policy or a setting?"
- **Dismissive, to show the mood rising:** "Calm down, it's probably something your team did."
- **Recover and own it:** "I'm sorry, that came out wrongly. I will take ownership of this and call you back by three o'clock with an update. Is there anything else I can help with today?"

## How demo mode is labelled

Say this once, early. Demo mode is never presented as a model.

- The app header shows "Demo mode". A live model shows "Live:" and its name instead.
- On the brief, **How your voice is handled** has a row "Who plays the customer", which says "Demo mode: the customer is played by Firefly's built-in rules engine."
- On the call page, the last pre-flight row, "Customer AI", reads "Demo mode: Firefly's built-in rules engine", and the call bar shows a "Demo mode" badge.
- On the report, the "Demo mode" badge sits by the title. **About this report** says "The customer was played by" Firefly's built-in rules engine (demo mode), not a language model, and that the coaching was written by Firefly's built-in rules evaluator (demo mode).
- Scripted speech is labelled "Demo speech (scripted)" on the brief and the pre-flight page.

## If something goes wrong

| What you see                                                                                                                | What to do                                                                                                                                                                                                                                                            |
| --------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "The microphone is blocked, so Firefly cannot hear you."                                                                    | Allow the microphone in the address bar and choose **Retry**, or choose **Use text**. A text call shows the same report.                                                                                                                                              |
| "No speech was detected." or "Firefly could not make out any words."                                                        | Say it again, a little closer to the microphone, or type. With browser speech this may repeat. Say plainly that browser recognition is the least reliable path, and type.                                                                                             |
| "Spoken calls are not available on this server right now."                                                                  | Speech is off or failing on the server. Type your replies, or start a text-only call from the brief.                                                                                                                                                                  |
| The customer's voice does not play ("The browser is waiting for a tap before it will play sound.", or it could not be made) | Choose **Replay**, or **Continue without audio**. The customer's words are in the transcript.                                                                                                                                                                         |
| "The customer could not reply." or "The customer is taking too long."                                                       | Choose **Retry**. Your message is kept and is never sent twice. The call waits 45 seconds for a reply before it shows "The customer is taking too long."                                                                                                              |
| "Messages are going too fast."                                                                                              | Wait the number of seconds shown, then choose **Retry**.                                                                                                                                                                                                              |
| The call shows "Paused" after you switched to another tab or window                                                         | A spoken call pauses by itself when its tab is hidden, and the microphone stays closed until you press **Resume**. A text call is not affected.                                                                                                                       |
| The customer repeats a phrasing in a long call (demo mode)                                                                  | Expected. The rules engine has a fixed set of phrasings. Say so and move on to the report.                                                                                                                                                                            |
| "Building your coaching report" stays on screen                                                                             | Wait. After a while the page says it is taking longer than usual, and you can read the transcript meanwhile. If it says "The coaching report could not be finished", choose **Retry evaluation**. The transcript is kept.                                             |
| "We could not find this call." or "This call could not be opened."                                                          | Choose **Retry** if it is offered, or go back to the scenarios and start again.                                                                                                                                                                                       |
| A live model fails or is rate limited                                                                                       | The message says what happened and offers **Retry**. See [troubleshooting.md](troubleshooting.md). If it keeps failing, stop the server, remove `FIREFLY_PROVIDER` from `.env`, restart in demo mode and start a new call. A call keeps the provider it started with. |

## What not to claim

- **Speech recognition.** Do not say it is accurate, enterprise-grade or tested with Azure. Azure AI Speech has not been run live. Browser recognition returned no words under automation. The scripted demo speech understands nothing.
- **The customer's voice.** Do not say it shows real emotion. Pace and pitch are adjusted, and a style for a few voices. The result has not been judged by a person.
- **The scores.** Do not say they are accurate, fair or comparable between people. They are practice signals, and they have not been compared with mentors' scores.
- **The rules engine.** Do not call it AI or a model. In demo mode there is no language model, and the app says so.
- **Live models.** Do not say one has been evaluated. Gemini had a limited smoke check, which says nothing about voice, other scenarios or paid-tier behaviour. Azure OpenAI and the OpenAI-compatible endpoint have not been run live.
- **CBCF.** Do not say Firefly is aligned with it. The mapping is not applied.
- **Interrupting.** Do not say you can talk over the customer. There is no barge-in.
- **Accessibility.** Do not claim more than automated checks. No screen reader or other assistive technology has been used to test it.
- **Deployment.** Do not say it is deployed, secure for real data or ready for production. There is no hosting configuration and no sign-in. It is a prototype for a trusted machine.
- **Data.** Never enter real customer information.

## After the demo

Stop the server with Ctrl+C in its terminal. Calls are kept in `data/firefly.db` (git-ignored) unless you used `FIREFLY_DB_PATH=:memory:`. To delete one call, open its report, choose **Delete this call**, then **Delete call**. To remove them all, delete the database file after the server has stopped. If you used a live model, remove or replace the key if it was ever shown on screen or pasted anywhere.
